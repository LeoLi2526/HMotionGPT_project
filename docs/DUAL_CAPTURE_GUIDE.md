# 臂环与戒指双设备工程采集

当前可统一创建试次、并行接收、保存原始数据、解析并生成共同的**电脑接收时间轴**。这是工程采集入口，尚不是经过误差验收的设备采样同步系统。相机未包含。

## 日常使用

1. 打开臂环本体、插入接收器；戒指开机并靠近电脑。厂商调试软件需释放串口和蓝牙连接。
2. 臂环维持已验证的 **8列、空格分隔文本模式，115200、8N1**。戒指保持当前已验证的50Hz配置；软件不切换频率或刷固件。
3. 双击项目根目录 `start_dual_capture.cmd`。按列表选择臂环接收器与戒指，填写被试、会话、试次及佩戴状态。
4. 等待结束。默认戒指记录30秒，臂环记录60秒，其中额外30秒用于覆盖蓝牙连接准备。两流真实接收重叠以报告为准，不能由启动时间推定。
5. 查看提示中的试次目录和 `dual_run/result.json`。`engineering_capture_ok: true` 只说明本次双路工程检查通过；`synchronization: unverified` 仍然有效。需要取消时按 Ctrl+C，等程序退出；不要直接关闭窗口，以免来不及生成完整报告。

此入口使用项目 `.venv/Scripts/python.exe`，复用既有 pyserial、bleak 环境。更换电脑时按项目设备安装说明配置环境与连接，不能只复制快捷入口。

## 多被试与多时间段

目录结构为 `data/episodes/<被试>/<会话>/<试次>/`。例如 `S001/20261113_AM/T001`、`S001/20261113_PM/T001`、`S002/20261113_PM/T001`。编号仅用英文、数字、下划线或连字符。重复试次会拒绝覆盖，重采请增加试次编号。

每次都记录任务、同意范围、臂环佩戴侧、戒指安装和供电状态；本入口固定为engineering用途。更换被试或重戴后，不能沿用未经验证的佩戴标定。正式被试采集资格仍需另行验收。

| 文件 | 用途 |
|---|---|
| `episode.json` | 被试、会话、任务、佩戴与用途 |
| `captures/dual01/source/…` | 臂环原始字节、电脑接收分块时间与校验 |
| `ring_captures/dual01/` | 戒指原始帧、通知、设备时钟、配置和TIME_SYNC往返证据 |
| `derived/dual01/rows.csv` | 臂环原值；无设备时间戳的字段保持空白 |
| `ring_derived/dual01/imu.csv` | 戒指原值、物理量、设备采集代、标称样本时间与接收时间 |
| `dual_derived/dual01/timeline/` | 两份接收相对时间CSV和重叠、掉流检查报告 |
| `dual_derived/dual01/processing.json` | 解析与校验汇总，含失败项 |
| `dual_run/` | 启动请求、两子进程日志、退出状态与最终结果 |

原始数据保持不变，处理结果另存。不要仅保存两份CSV而丢掉原始帧和时间日志。失败试次也保留，用于排查，不能改名混入成功试次。

## 时间轴怎么使用

`host_relative_seconds` 是两路接收时间减去同一电脑此次启动原点，单位秒；`in_overlap` 标记是否处在两流接收范围交集。每份CSV保留全部原字段，没有强行重采样成相同频率。戒指一个蓝牙批次的多个样本会共享接收时间，这是保留实际传输行为，不是记录错误。

工程检查要求两路正常结束、原始校验通过、臂环有8列有效行且无中间坏行、戒指有有效实时样本且无坏帧或配置冲突、实际接收范围重叠至少达到请求时长的80%，且最大接收间断不超过2秒。80%和2秒只是当前工程筛查设置，**不代表同步误差要求或已测精度**。臂环中途接入可能留下不完整首行：仅第0行且字节偏移为0的坏行单独标作未验证起始边界，排除出时间轴；尾部残片也单独记录，原始字节和原解析QC保持不变，其余坏行仍失败。

目前臂环没有已确认的设备时间戳；戒指有设备时钟，但蓝牙批量发送产生延迟。两流接收时间相近不能证明两个物理动作发生在同一时刻。不能把EMG峰值直接对齐IMU峰值来消除传输延迟。后续需要可共同观测的同步事件、时钟段拟合和独立留出事件验证，才能得到误差范围；未完成前不用于精细相位或毫秒级融合结论。

## 可脚本调用

从项目根目录调用 `scripts/dual_capture.py record --help` 查看参数。必须明确提供 `--port` 和 `--address`，禁止照搬其他电脑地址。`--subject`、`--session`、`--trial`、`--task`、`--consent-scope` 是必要的试次字段。采集时长范围1–3600秒；长时稳定性尚未验收。单次记录只使用同一主机单调时钟，不直接合并跨电脑或跨重启的该字段。

需要重新解析本入口创建的试次时，运行 `scripts/dual_capture.py process --episode <试次目录> --derive-id <新的处理编号>`；原采集判定不会被改写，重新处理目录也不能覆盖旧目录。`inspect`只查询状态和校验，不生成时间轴。

## 本机实测（2026-11-13）

最终短采T003：臂环3014行、戒指765个实时六轴样本，两路接收范围重叠14.984秒；无中间坏行、无戒指坏帧，双路正常退出。详见 `knowledge_base/devices/dual_platform_2026-11-13.md`。这验证单入口短采链路；交互向导未由操作者完整走一轮，长时记录和同步精度尚未验收。
