## 再次接入或复采

1. 记录臂环铭牌、软件/固件版本、接收器型号及前臂佩戴位置。按厂商教程配对并开启数据输出。若需要注册码，应通过厂家或已有授权取得；不要将注册码写入 Git。
2. 在项目根目录运行 `\.venv\Scripts\python.exe scripts\sichiray_capture.py ports`。以接收器信息和连接前后的端口变化确认 `COMx`，不能按旧脚本固定选端口；重新插拔或换电脑后端口可能变化。当前主机的具体端口记录在被忽略的 `config/host.local.yaml`。
3. 关闭占用同一串口的上位机，再进行一次 60 秒静止、握拳/放松、手臂转动的短采。用实际端口替换 `COMx`：

   ```powershell
   .\.venv\Scripts\python.exe scripts\sichiray_capture.py capture --port COMx --baud 115200 --seconds 60 --label first_contact
   ```

   若实际端口需要其他波特率，按设备/接收器说明改 `--baud`。程序不会自动扫描或试开所有端口。
4. 程序打印会话目录；用该目录执行 `\.venv\Scripts\python.exe scripts\sichiray_capture.py inspect <会话目录>`。检查收到的字节数、8/9/14 整数文本行数或候选 98 字节 HEX 帧数。即使检查结果是“未知格式”，也保留原始文件供协议核对。
5. 另行用厂商上位机的专业模式保存一个短样本，并记录导出设置、文件格式与软件版本。当前调试助手曾以“16进制”、5 通道、`uint8` 解析，与实测的 8 列十进制文本不匹配；先停止记录，改为 ASCII、8 通道、**空格分隔**和已验证的 `115200` 波特率，再重新录制。选“其他”分隔符时界面已显示读到一整行八个整数，但绘图统计为 `0sps`。若上位机和采集程序使用同一串口，分别运行。上位机的“插入时间戳”选项需检查其实际导出字段和时钟来源，不能仅凭勾选就认定为设备时间戳。对比两种输出后再确定正式采集路径。

2026-11-05 已用上述 ASCII 设置成功导出八列、402 行的 CSV 样本；另一次勾选“插入时间戳”后导出 5,361 行九列数据。该时间列是与文件创建时间一致的 Unix 整秒值，推断为上位机主机时间，不能当作设备采样时钟；详见[实机初检](../knowledge_base/devices/sichiray_n1_2026-11-05.md)。

## 输出和判定边界

每次采集写入被 Git 忽略的 `data/sichiray/<UTC时间>_<标签>/`：`serial_raw.bin` 是原始字节，`receive_chunks.jsonl` 记录字节偏移、长度及主机读取完成时间，`metadata.json` 记录端口、配置、状态、字节数和 SHA-256。主机读取时间**不是**每个 EMG 样本的采样时刻；离线检查中的 HEX 帧、长度字节和大端时间戳也只是厂商文档结构的候选匹配。实机样本到手后还需确认实际数据格式、设备时钟单位、通道值的有符号性、EMG 帧内时序与丢包率。

本机已观察到 8 列约 67 行/秒、9 列约 50 行/秒、14 列约 25 行/秒的模式循环。8 列为 EMG 候选，9 列为惯性候选，14 列为惯性＋EMG 合并候选；这些只是**串口输出行率和字段推断**，不等于内部 ADC 采样率。三种模式都没有明确设备时间戳，正式三模态同步前需解决设备时钟或可复核的外部同步方式。

若采集为 0 字节，先检查端口归属、蓝牙接收器、设备输出模式、串口占用和波特率，并保留该次 `metadata.json`。8 列模式不含惯性候选字段；14 列模式虽然同时携带两类候选字段，仍不提供文档所述设备时间戳。不能以主机读取时间冒充同步后的设备时间。

在另一台电脑重新准备时，从项目根目录执行 `python -m venv .venv` 和 `.\.venv\Scripts\python.exe -m pip install -r requirements-sichiray.txt`；调试助手压缩包需在该主机的获准位置单独取得，不随公开仓库同步。
